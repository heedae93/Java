## 1. 지역 변수와 스코프

변수는 선언한 위치에 따라 **지역 변수**, **멤버 변수**(클래스 변수, 인스턴스 변수)로 분류됩니다.
지금까지 학습한 변수는 모두 **지역 변수(Local Variable)** 입니다. 나머지 변수는 뒤에서 학습합니다.

- 지역 변수는 이름 그대로 **특정 지역에서만 사용할 수 있는 변수**입니다.
- 여기서 말하는 지역이 바로 변수가 선언된 **코드 블록(`{}`)** 입니다.
- 지역 변수는 자신이 선언된 코드 블록 안에서만 생존하고, 코드 블록을 벗어나면 **제거**됩니다. 따라서 이후에는 접근할 수 없습니다.

이렇게 **변수의 접근 가능한 범위**를 **스코프(Scope)** 라고 합니다. Scope 를 번역하면 범위라는 뜻입니다.

```java
// Scope1
public static void main(String[] args) {
    int m = 10; //m 생존 시작
    if (true) {
        int x = 20; //x 생존 시작
        System.out.println("if m = " + m); //블록 내부에서 블록 외부는 접근 가능
        System.out.println("if x = " + x);
    } //x 생존 종료
    //System.out.println("main x = " + x); //오류, 변수 x에 접근 불가
    System.out.println("main m = " + m);
} //m 생존 종료
```

| 변수 | 선언 위치 | 생존 범위 | 스코프 |
|---|---|---|---|
| `m` | `main{}` | 선언한 시점 ~ `main{}` 끝 | 넓음 |
| `x` | `if{}` | 선언한 시점 ~ `if{}` 끝 | 좁음 |

## 2. 블록 밖에서 사용하면 컴파일 에러

```java
if (true) {
    int x = 20;
}
System.out.println(x);   // X 컴파일 에러: cannot find symbol
```

`cannot find symbol` 은 **변수 이름을 찾을 수 없다**는 뜻입니다. 오타가 아니라면 스코프를 먼저 의심하세요.

### 2-1. `for` 문의 초기식 변수 (`Scope2`)

`for(int i = 0; ...)` 처럼 초기식에서 직접 선언한 변수는 **`for` 문 코드 블록 안에서만** 사용할 수 있습니다.

```java
int m = 10;
for (int i = 0; i < 2; i++) { //블록 내부, for문 내
    System.out.println("for m = " + m); //블록 내부에서 블록 외부는 접근 가능
    System.out.println("for i = " + i);
} //i 생존 종료
//System.out.println("main i = " + i); //오류, i에 접근 불가
```

### 2-2. 선언 위치는 "변수를 사용하는 가장 바깥 블록"

블록 안에서 값을 정하고 블록 **밖에서** 사용해야 한다면, 변수를 블록 **밖에서** 선언해야 합니다.

```java
// X
if (age >= 18) {
    String status = "성인";
} else {
    String status = "미성년자";
}
System.out.println(status);  // 컴파일 에러: 두 status 모두 이미 사라짐

// O CondOp1
String status;
if (age >= 18) {
    status = "성인";
} else {
    status = "미성년자";
}
System.out.println(status);
```

> 이 경우 `else` 가 없으면 `variable might not have been initialized` 에러가 납니다. (`variable/변수_초기화.md` 참고)

## 3. 같은 이름의 변수를 다시 선언할 수 없다

안쪽 블록에서는 바깥 변수가 **아직 살아 있기 때문에** 같은 이름으로 다시 선언할 수 없습니다.

```java
int m = 10;
if (true) {
    int m = 20;   // X 컴파일 에러: variable m is already defined in method main
}
```

반면, 스코프가 **겹치지 않으면** 같은 이름을 다시 사용할 수 있습니다.

```java
if (true) {
    int x = 1;
}               // x 제거
if (true) {
    int x = 2;  // O 위의 x 는 이미 사라졌으므로 가능
}

for (int i = 0; i < 3; i++) { }
for (int i = 0; i < 5; i++) { }  // O 그래서 for 문마다 i 를 계속 쓸 수 있다
```

중첩 반복문에서 안쪽 변수 이름을 바깥과 다르게(`i`, `j`) 짓는 이유도 이것입니다.

```java
for (int i = 0; i < 3; i++) {
    for (int i = 0; i < 3; i++) { }  // X 컴파일 에러
}
```

## 4. 반복문 안에서 선언한 변수는 매번 새로 만들어진다

반복문의 코드 블록은 **한 번 반복할 때마다 시작되고 끝납니다.** 따라서 블록 안에서 선언한 변수는 매 반복마다 새로 만들어지고 사라집니다.

```java
// X sum 이 매번 0 으로 새로 만들어짐
for (int i = 1; i <= 3; i++) {
    int sum = 0;
    sum += i;
    System.out.println(sum);  // 1, 2, 3 (누적되지 않음)
}

// O 누적 값은 반복문 밖에서 선언
int sum = 0;
for (int i = 1; i <= 3; i++) {
    sum += i;
}
System.out.println(sum);      // 6
```

> 정리: **반복할 때마다 유지되어야 하는 값**은 반복문 밖에, **한 번의 반복 안에서만 쓰는 값**은 반복문 안에 선언합니다.

## 5. 스코프는 꼭 필요한 곳으로 한정하자

변수를 선언한 시점부터 계속 사용할 수 있게 해도 되지 않을까? 왜 굳이 스코프라는 개념을 만들었을까?

```java
// Scope3_1 - 좋지 않은 코드
int m = 10;
int temp = 0;            // if 에서만 쓰는데 main 전체가 스코프
if (m > 0) {
    temp = m * 2;
    System.out.println("temp = " + temp);
}
System.out.println("m = " + m);
```

임시 변수 `temp` 는 `if` 조건이 만족할 때 임시로 잠깐 사용하는 변수입니다. 그런데 `main()` 코드 블록에 선언되어 있어서 다음과 같은 문제가 생깁니다.

- **비효율적인 메모리 사용**: `temp` 는 `if` 코드 블록에서만 필요하지만, `main()` 코드 블록이 종료될 때까지 메모리에 유지됩니다. `if` 안에 선언했다면 `if` 코드 블록이 끝나는 시점에 메모리에서 제거되어 더 효율적으로 메모리를 사용할 수 있습니다.
- **코드 복잡성 증가**: `if` 가 끝나도 `main()` 어디서나 `temp` 에 여전히 접근할 수 있습니다. 누군가 이 코드를 유지보수할 때 `m` 은 물론이고 `temp` 까지 계속 신경써야 합니다. 스코프가 불필요하게 넓은 것입니다.

```java
// Scope3_2 - 좋은 코드
int m = 10;
if (m > 0) {
    int temp = m * 2;    // 스코프를 if 블록으로 한정
    System.out.println("temp = " + temp);
}
System.out.println("m = " + m);
```

### 5-1. 스코프 관점에서 `while` vs `for`

```java
// While2_3 - i 의 스코프: main() 전체
int i = 1;
while (i <= endNum) {
    ...
    i++;
}
//... 아래에 더 많은 코드들이 있다고 가정 → 여기서도 i 를 신경써야 함

// For2 - i 의 스코프: for 문 안
for (int i = 1; i <= endNum; i++) {
    ...
}
//... 여기서는 i 를 신경쓸 필요 없음
```

변수 `i` 와 같이 `for` 문 안에서만 사용되는 카운터 변수가 있다면 `while` 문보다는 `for` 문을 사용해서 스코프의 범위를 제한하는 것이 메모리 사용과 유지보수 관점에서 더 좋습니다.

> 핵심: **좋은 프로그램은 무한한 자유가 있는 프로그램이 아니라 적절한 제약이 있는 프로그램이다.**

## 6. 정리 체크리스트

- [ ] 지역 변수는 선언된 `{}` 블록 안에서만 사용 가능
- [ ] 안쪽 블록 → 바깥 변수 접근 O / 바깥 → 안쪽 변수 접근 X
- [ ] `cannot find symbol` 이 나면 스코프를 확인
- [ ] 블록 밖에서도 써야 하는 값은 블록 밖에서 선언
- [ ] 살아 있는 변수와 같은 이름으로 다시 선언 불가
- [ ] 반복마다 유지할 값(누적 변수)은 반복문 밖에서 선언
- [ ] 변수의 스코프는 꼭 필요한 곳으로 한정 (카운터 변수는 `for` 문)
