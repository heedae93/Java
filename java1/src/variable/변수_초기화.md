# 변수 초기화 정리

## 한눈에 보기

| 변수 종류 | 초기화 안 하고 사용하면? | 이유 |
|---|---|---|
| 지역 변수 (메서드 안) | **컴파일 에러** | 자바가 기본값을 넣어주지 않음 |
| 인스턴스 변수 (필드) | 기본값 자동 (`0`, `false`, `null` …) | 객체 생성(`new`) 시 자동 초기화 |
| 클래스 변수 (`static` 필드) | 기본값 자동 | 클래스 로딩 시 자동 초기화 |
| 배열 원소 | 기본값 자동 | 배열 생성(`new int[3]`) 시 자동 초기화 |
| 매개변수 | 초기화 필요 없음 | 호출할 때 반드시 값이 전달됨 |
| `final` 필드 | **컴파일 에러** (값을 안 넣으면) | 한 번은 반드시 값을 넣어야 함 |

> 핵심: **지역 변수는 값을 넣기 전에 읽으면 컴파일 에러**가 납니다. 런타임 에러가 아닙니다.
> 필드와 배열은 자바가 기본값을 넣어주므로 에러가 나지 않습니다.

---

## 1. 초기화란?

변수를 선언하고 **처음으로 값을 넣는 것**을 초기화라고 합니다.

```java
int a;      // 선언만 함 (값이 없음)
a = 10;     // 초기화 (처음으로 값을 넣음)

int b = 20; // 선언과 동시에 초기화
```

---

## 2. 왜 지역 변수는 초기화하고 사용해야 할까?

### 2-1. 값이 정해지지 않은 변수는 의미가 없다

변수를 사용한다는 것은 그 안에 있는 **값을 읽는다**는 뜻입니다.
값을 넣은 적이 없는데 읽으면 무슨 값이 나와야 할지 정할 수 없습니다.

```java
public static void main(String[] args) {
    int a;
    System.out.println(a); // 컴파일 에러
    // java: variable a might not have been initialized
}
```

### 2-2. 메모리에 남아 있는 쓰레기 값을 막기 위해

지역 변수는 메서드가 실행될 때 **스택(Stack)** 메모리에 만들어집니다.
그 메모리 위치에는 이전에 다른 메서드가 쓰던 값이 남아 있을 수 있습니다.

C 언어는 초기화하지 않은 지역 변수를 그냥 읽게 해 줍니다. 그래서 실행할 때마다 다른 이상한 값(쓰레기 값)이 나오는 버그가 자주 생깁니다.

```c
// C 언어 예시 - 컴파일은 되지만 어떤 값이 나올지 모름
int a;
printf("%d", a); // 12345? -8723? 매번 다를 수 있음
```

자바는 이런 버그를 **아예 컴파일 단계에서 막도록** 설계되었습니다.

### 2-3. 그럼 왜 지역 변수에는 기본값을 넣어주지 않을까?

자바가 지역 변수에도 `0`을 자동으로 넣어주면 컴파일 에러는 사라집니다. 하지만 이렇게 하지 않은 이유가 있습니다.

1. **실수를 숨기지 않기 위해**
   개발자가 값을 넣는 것을 깜빡했다면 그건 대부분 버그입니다.
   자동으로 `0`이 들어가면 프로그램은 돌아가지만 **틀린 결과**가 나오고, 원인을 찾기 어렵습니다.
   컴파일 에러로 알려주는 쪽이 훨씬 빨리 실수를 발견할 수 있습니다.

2. **컴파일러가 확인할 수 있기 때문에**
   지역 변수는 하나의 메서드 안에서만 쓰입니다. 그래서 컴파일러가 코드 흐름을 따라가며 "읽기 전에 값이 반드시 들어갔는지"를 확인할 수 있습니다.
   이 검사를 **확정적 할당(Definite Assignment)** 검사라고 부릅니다.

3. **성능**
   메서드는 아주 자주 호출됩니다. 호출할 때마다 모든 지역 변수를 `0`으로 채우는 작업은 낭비가 될 수 있습니다.

## 3. 컴파일 에러가 나는 경우 (지역 변수)

### 3-1. 기본 예시

```java
int a;
System.out.println(a); // 컴파일 에러
```

### 3-2. 선언만 하고 사용하지 않으면? → 에러 아님

```java
int a; // 사용하지 않으면 에러가 나지 않음 (IDE가 경고 정도만 표시)
```

에러는 **선언할 때가 아니라 값을 읽을 때** 납니다.

### 3-3. 연산에 사용하는 경우

```java
int sum;
sum = sum + 10; // 컴파일 에러: 오른쪽의 sum을 읽는데 값이 없음
```

```java
int sum;
sum += 10;      // 컴파일 에러: sum = sum + 10 과 같은 의미
```

```java
int i;
i++;            // 컴파일 에러: i = i + 1 과 같은 의미
```

### 3-4. 반복문으로 합계를 구할 때 (가장 흔한 실수)

```java
int sum; // 초기화 안 함
for (int i = 1; i <= 10; i++) {
    sum += i;   // 컴파일 에러
}
```

```java
int sum = 0; // 올바른 코드: 0부터 더해 나가야 함
for (int i = 1; i <= 10; i++) {
    sum += i;
}
System.out.println(sum); // 55
```

### 3-5. if 문에서 일부 경우에만 값을 넣은 경우

```java
int age = 20;
String result;
if (age >= 18) {
    result = "성인";
}
System.out.println(result); // 컴파일 에러
// age가 18 미만이면 result에 값이 없기 때문
```

컴파일러는 `age`가 20이라는 것을 따지지 않습니다. **조건이 false가 될 가능성이 있으면** 값이 없을 수 있다고 판단합니다.

### 3-6. if - else if 만 있고 else가 없는 경우

```java
int score = 85;
String grade;
if (score >= 90) {
    grade = "A";
} else if (score >= 80) {
    grade = "B";
}
System.out.println(grade); // 컴파일 에러: 둘 다 아니면 값이 없음
```

### 3-7. switch 문에 default가 없는 경우

```java
int month = 3;
String season;
switch (month) {
    case 3:
    case 4:
    case 5:
        season = "봄";
        break;
    case 6:
        season = "여름";
        break;
}
System.out.println(season); // 컴파일 에러: 어떤 case에도 안 맞으면 값이 없음
```

### 3-8. 반복문 안에서만 값을 넣은 경우

```java
int last;
for (int i = 0; i < 5; i++) {
    last = i;
}
System.out.println(last); // 컴파일 에러
// 컴파일러는 반복문이 한 번도 실행되지 않을 수 있다고 판단함
```

### 3-9. try 안에서만 값을 넣은 경우

```java
String input = "abc";
int number;
try {
    number = Integer.parseInt(input);
} catch (NumberFormatException e) {
    System.out.println("숫자가 아닙니다.");
}
System.out.println(number); // 컴파일 에러
// 예외가 발생하면 number에 값이 들어가지 않기 때문
```

### 3-10. var는 선언과 동시에 초기화해야 함 (Java 10+)

```java
var a;      // 컴파일 에러: var는 값을 보고 타입을 정하므로 값이 꼭 필요
var b = 10; // OK (int로 추론)
```

## 4. 초기화를 나중에 해도 되는 경우 (지역 변수)

지역 변수라도 **읽기 전에 모든 경우에 값이 들어간다**는 것을 컴파일러가 확인할 수 있으면 에러가 나지 않습니다.

### 4-1. 선언 후 사용하기 전에 값을 넣는 경우

```java
int a;
a = 10;
System.out.println(a); // OK
```

### 4-2. if - else 의 모든 경우에 값을 넣는 경우

```java
int age = 15;
String result;
if (age >= 18) {
    result = "성인";
} else {
    result = "미성년자";
}
System.out.println(result); // OK: 어떤 경우든 값이 들어감
```

### 4-3. switch 에 default 가 있는 경우

```java
int month = 3;
String season;
switch (month) {
    case 3, 4, 5 -> season = "봄";
    case 6, 7, 8 -> season = "여름";
    case 9, 10, 11 -> season = "가을";
    default -> season = "겨울";
}
System.out.println(season); // OK
```

### 4-4. try 와 catch 모두에서 값을 넣는 경우

```java
String input = "abc";
int number;
try {
    number = Integer.parseInt(input);
} catch (NumberFormatException e) {
    number = 0;
}
System.out.println(number); // OK: 0
```

### 4-5. 상수 조건(`true`)을 쓰는 경우

컴파일러는 `true` 같은 **상수 조건**은 결과를 알 수 있으므로 예외적으로 허용합니다.

```java
int a;
while (true) {
    a = 10;
    break;
}
System.out.println(a); // OK: 반드시 한 번은 실행됨
```

하지만 변수로 된 조건은 값이 `true`여도 안 됩니다.

```java
boolean flag = true;
int a;
while (flag) {
    a = 10;
    break;
}
System.out.println(a); // 컴파일 에러: 컴파일러는 flag 값을 따지지 않음
```

### 4-6. 나중에 초기화하면 좋은 경우: 값이 상황에 따라 달라질 때

이럴 때는 의미 없는 값으로 미리 초기화하기보다 **선언만 하고 각 경우에 값을 넣는 것**이 더 좋습니다.

```java
// 좋지 않은 예: 의미 없는 "" 로 초기화
String grade = "";
if (score >= 90) {
    grade = "A";
} else if (score >= 80) {
    grade = "B";
}
// 실수로 경우를 빠뜨려도 컴파일러가 알려주지 못함 → grade가 "" 인 채로 출력됨
```

```java
// 좋은 예: 선언만 하고 모든 경우에 값을 넣음
String grade;
if (score >= 90) {
    grade = "A";
} else if (score >= 80) {
    grade = "B";
} else {
    grade = "C";
}
// else를 빠뜨리면 컴파일러가 에러로 알려줌
```

> 컴파일 에러를 없애려고 의미 없는 값(`0`, `""`, `null`)을 넣는 습관은 실수를 숨길 수 있습니다.

## 5. 초기화하지 않아도 되는 경우 (자동 초기화)

### 5-1. 기본값 표

| 타입 | 기본값 |
|---|---|
| `byte`, `short`, `int` | `0` |
| `long` | `0L` |
| `float` | `0.0f` |
| `double` | `0.0` |
| `char` | `'\u0000'` (아무 글자도 없는 문자) |
| `boolean` | `false` |
| 참조형 (`String`, 배열, 객체 등) | `null` |

### 5-2. 인스턴스 변수 (필드)

```java
public class Member {
    String name;  // null
    int age;      // 0
    boolean vip;  // false

    public static void main(String[] args) {
        Member member = new Member();
        System.out.println(member.name); // null
        System.out.println(member.age);  // 0
        System.out.println(member.vip);  // false
    }
}
```

**왜 필드는 자동으로 초기화할까?**
- 필드는 객체가 살아 있는 동안 여러 메서드에서 사용됩니다. 어떤 메서드가 어떤 순서로 호출될지 컴파일러가 알 수 없어서 "값이 들어갔는지"를 확인할 방법이 없습니다.
- 그래서 자바는 `new`로 객체를 만들 때 **힙(Heap) 메모리를 0으로 깨끗하게 채워** 쓰레기 값이 생기지 않게 보장합니다.

### 5-3. 클래스 변수 (static 필드)

```java
public class Counter {
    static int count; // 0

    public static void main(String[] args) {
        count++;
        System.out.println(count); // 1
    }
}
```

### 5-4. 배열 원소

배열은 `new`로 만들 때 모든 칸이 기본값으로 채워집니다.
배열을 **지역 변수로 선언해도** 원소는 자동 초기화됩니다.

```java
public static void main(String[] args) {
    int[] scores = new int[3];
    System.out.println(scores[0]); // 0

    String[] names = new String[2];
    System.out.println(names[0]);  // null

    boolean[] checks = new boolean[2];
    System.out.println(checks[0]); // false
}
```

단, **배열 변수 자체**는 지역 변수이므로 초기화해야 합니다.

```java
int[] arr;
System.out.println(arr[0]); // 컴파일 에러: arr 자체에 값이 없음
```

### 5-5. 매개변수

매개변수는 메서드를 호출할 때 반드시 값이 전달되므로 초기화할 필요가 없습니다.

```java
public static int add(int a, int b) { // a, b는 호출 시 값이 들어옴
    return a + b;
}

add(1, 2); // a = 1, b = 2
```

## 6. final 변수의 초기화

`final`은 **값을 한 번만 넣을 수 있는** 변수입니다.

### 6-1. final 지역 변수

```java
final int a;
a = 10;  // OK: 처음 한 번은 넣을 수 있음
a = 20;  // 컴파일 에러: 이미 값이 들어감
```

### 6-2. final 필드는 자동 초기화되지 않음

일반 필드와 달리 `final` 필드는 기본값이 들어가지 않습니다. 선언할 때나 생성자에서 **반드시** 값을 넣어야 합니다.

```java
public class Member {
    final String id; // 컴파일 에러: 값을 넣는 곳이 없음
}
```

```java
public class Member {
    final String id;

    public Member(String id) {
        this.id = id; // OK: 생성자에서 초기화
    }
}
```

```java
public class Config {
    static final int MAX_SIZE = 100; // static final은 선언할 때(또는 static 블록에서) 초기화
}
```

## 7. 자동 초기화를 믿으면 생기는 런타임 문제

필드와 배열은 컴파일 에러가 나지 않지만, 기본값 때문에 **실행 중에 문제가 생길 수 있습니다.**

### 7-1. NullPointerException (런타임 에러)

```java
public class Member {
    String name; // null

    public static void main(String[] args) {
        Member member = new Member();
        System.out.println(member.name.length()); // 런타임 에러: NullPointerException
    }
}
```

```java
String[] names = new String[3];       // 모든 칸이 null
System.out.println(names[0].length()); // 런타임 에러: NullPointerException
```

### 7-2. 에러는 안 나지만 틀린 결과 (논리 오류)

```java
public class Product {
    String name;
    int price; // 가격을 넣는 것을 깜빡함 → 0

    public static void main(String[] args) {
        Product product = new Product();
        product.name = "노트북";
        System.out.println(product.name + " 가격: " + product.price); // 노트북 가격: 0
    }
}
```

에러가 없어서 바로 눈치채기 어렵습니다. 그래서 필드도 생성자에서 필요한 값을 받아 초기화하는 것이 좋습니다.

---

## 8. 정리: 컴파일 에러 vs 런타임 에러

| 상황 | 결과 |
|---|---|
| 초기화 안 한 지역 변수를 읽음 | **컴파일 에러** (`variable might not have been initialized`) |
| `final` 필드를 초기화하지 않음 | **컴파일 에러** |
| 필드/배열 원소를 초기화 안 하고 읽음 | 에러 없음 (기본값 사용) |
| `null`인 필드/배열 원소로 메서드 호출 | **런타임 에러** (`NullPointerException`) |
| 숫자 필드를 깜빡하고 `0`인 채로 사용 | 에러 없음, **틀린 결과** |

## 9. 좋은 습관

1. 변수는 **사용하기 직전에** 선언하고, 가능하면 **선언과 동시에 의미 있는 값**으로 초기화합니다.
   ```java
   int sum = 0;
   Scanner scanner = new Scanner(System.in);
   ```
2. 합계·개수를 셀 때는 반드시 시작값(`0`)으로 초기화합니다.
3. 경우에 따라 값이 달라지면 **의미 없는 값으로 미리 채우지 말고** 모든 경우(`else`, `default`, `catch`)에 값을 넣습니다. 빠뜨리면 컴파일러가 알려줍니다.
4. 한 번 정하면 바뀌지 않는 값은 `final`을 붙입니다.
5. 필드는 생성자에서 필요한 값을 받아 초기화해 `null`이나 `0`이 남지 않게 합니다.
