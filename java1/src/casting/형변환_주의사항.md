## 1. 자동 형변환 (묵시적 형변환)

자바에서 숫자를 표현할 수 있는 범위는 다음과 같습니다.

```
int < long < double
```

**작은 범위에서 큰 범위로의 대입은 허용**합니다. 쉽게 이야기하면 큰 그릇은 작은 그릇에 담긴 내용물을 담을 수 있습니다.

```java
// Casting1
int intValue = 10;
long longValue;
double doubleValue;

longValue = intValue;    // int -> long
System.out.println("longValue = " + longValue);       //longValue = 10

doubleValue = intValue;  // int -> double
System.out.println("doubleValue1 = " + doubleValue);  //doubleValue1 = 10.0

doubleValue = 20L;       // long -> double
System.out.println("doubleValue2 = " + doubleValue);  //doubleValue2 = 20.0
```

결국 대입하는 형(타입)을 맞추어야 하기 때문에 개념적으로는 다음과 같이 동작합니다.

```java
//intValue = 10
doubleValue = intValue
doubleValue = (double) intValue //형 맞추기
doubleValue = (double) 10       //변수 값 읽기
doubleValue = 10.0              //형변환
```

이 과정이 자동으로 일어나기 때문에 **자동 형변환** 또는 **묵시적 형변환**이라고 합니다.

> 주의: `int` → `double` 로 바뀌면 출력에 `.0` 이 붙습니다. `10` 이 아니라 `10.0` 이 출력되는 것이 정상입니다.

> 참고: `long` → `double` 은 자동 형변환되지만, 아주 큰 `long` 값은 `double` 의 정밀도(약 15자리) 때문에 **끝자리가 달라질 수 있습니다.**
> ```java
> long big = 9007199254740993L;
> double d = big;
> System.out.println((long) d); // 9007199254740992 (끝자리 3 → 2)
> ```

## 2. 명시적 형변환

### 2-1. 큰 범위 → 작은 범위는 컴파일 에러

```java
// Casting2
double doubleValue = 1.5;
int intValue = 0;
//intValue = doubleValue; //컴파일 오류 발생
```

```
java: incompatible types: possible lossy conversion from double to int
//java: 호환되지 않는 유형: double에서 int로의 가능한 손실 변환
```

`int` 형은 `double` 형보다 숫자의 표현 범위가 작고, 실수를 표현할 수도 없습니다. 따라서 숫자가 손실되는 문제가 발생할 수 있습니다. 쉽게 이야기해서 큰 컵에 담긴 물을 작은 컵에 옮겨 담으려고 하니, 손실이 발생할 수 있다는 것입니다.

이런 문제는 매우 큰 버그를 유발할 수 있습니다. 예를 들어서 은행 프로그램이 고객에게 은행 이자를 계산해서 입금해야 하는데 이런 코드가 아무런 오류 없이 수행된다면 끔찍한 문제를 만들 수 있습니다. 그래서 자바는 이런 경우 컴파일 오류를 발생시킵니다. **컴파일 오류는 문제를 가장 빨리 발견할 수 있는 좋은 오류**입니다.

### 2-2. 직접 형변환 `(타입)`

위험을 개발자가 직접 감수하고도 값을 대입하고 싶다면 데이터 타입을 강제로 변경할 수 있습니다.

```java
intValue = (int) doubleValue; //형변환
System.out.println(intValue); //출력:1
```

```java
//doubleValue = 1.5
intValue = (int) doubleValue;
intValue = (int) 1.5; //doubleValue에 있는 값을 읽는다.
intValue = 1;         //(int)로 형변환 한다. intValue에 int형인 숫자 1을 대입한다.
```

- 형(타입)을 바꾼다고 해서 **형변환**, 영어로 **캐스팅**이라고 합니다.
- 개발자가 직접 형변환 코드를 입력한다고 해서 **명시적 형변환**이라고 합니다.

> 캐스팅 용어: "캐스팅"은 영어 단어 "cast"에서 유래되었습니다. "cast"는 금속이나 다른 물질을 녹여서 특정한 형태나 모양으로 만드는 과정을 의미합니다.

## 3. `(int)` 는 반올림이 아니라 **버림**

명시적 형변환은 소수점 이하를 **그냥 버립니다.** 반올림하지 않습니다.

```java
System.out.println((int) 1.5);   // 1
System.out.println((int) 1.9);   // 1  (2 가 아님!)
System.out.println((int) -1.9);  // -1 (-2 가 아님! 0 쪽으로 버림)
```

반올림이 필요하면 `Math.round()` 를 사용합니다.

```java
System.out.println(Math.round(1.5));  // 2
System.out.println(Math.round(1.4));  // 1
```

## 4. 형변환해도 원래 변수는 바뀌지 않는다

형변환을 한다고 해서 `doubleValue` 자체의 타입이 변경되거나 그 안에 있는 값이 변경되는 것이 아닙니다.
`doubleValue` 에서 **읽은 값을 형변환**하는 것입니다. `doubleValue` 안에 들어있는 값은 `1.5` 로 그대로 유지됩니다.

```java
double doubleValue = 1.5;
int intValue = (int) doubleValue;
System.out.println(intValue);     // 1
System.out.println(doubleValue);  // 1.5 (그대로)
```

> 참고로 변수의 값은 대입 연산자(`=`)를 사용해서 **직접 대입할 때만** 변경됩니다.

## 5. 형변환과 오버플로우

형변환을 할 때 작은 숫자가 표현할 수 있는 범위를 넘어서면 어떻게 될까?

```java
// Casting3
long maxIntValue = 2147483647;  //int 최고값
long maxIntOver = 2147483648L;  //int 최고값 + 1(초과)
int intValue = 0;

intValue = (int) maxIntValue;   //형변환
System.out.println("maxIntValue casting=" + intValue); //출력:2147483647

intValue = (int) maxIntOver;    //형변환
System.out.println("maxIntOver  casting=" + intValue); //출력:-2147483648
```

- **정상 범위**: `2147483647` 은 `int` 로 표현할 수 있는 범위에 포함되므로 `long` → `int` 로 형변환해도 아무런 문제가 없습니다.
- **초과 범위**: `2147483648L` 은 `int` 로 표현할 수 있는 범위를 넘기 때문에 전혀 다른 숫자 `-2147483648` 이 됩니다. 이런 현상을 **오버플로우**라고 합니다.

보통 오버플로우가 발생하면 마치 시계가 한바퀴 돈 것처럼 다시 처음부터 시작합니다. 참고로 `-2147483648` 숫자는 `int` 의 가장 작은 숫자입니다.

> 중요한 것은 **오버플로우가 발생하는 것 자체가 문제**라는 점입니다!
> 오버플로우가 발생했을 때 결과가 어떻게 되는지 계산하는데 시간을 낭비하면 안 됩니다! **오버플로우 자체가 발생하지 않도록 막아야 합니다.**
> 이 경우 단순히 대입하는 변수(`intValue`)의 타입을 `int` → `long` 으로 변경해서 사이즈를 늘리면 오버플로우 문제가 해결됩니다.

> 주의: 오버플로우는 **컴파일 에러도, 실행 에러도 나지 않습니다.** 조용히 틀린 값이 들어가므로 가장 찾기 어려운 버그 중 하나입니다.

### 5-1. 계산 도중의 오버플로우

결과를 `long` 에 담아도, **계산이 `int` 끼리** 이뤄지면 계산 단계에서 이미 오버플로우가 발생합니다.

```java
long x = 100000 * 100000;      // X 1410065408 (int * int 에서 이미 오버플로우)
long y = 100000L * 100000;     // O 10000000000 (long * int → long * long)
long z = (long) 100000 * 100000; // O
```

## 6. 계산과 형변환

형변환은 대입뿐만 아니라, **계산을 할 때도** 발생합니다.

```java
// Casting4
int div1 = 3 / 2;
System.out.println("div1 = " + div1); //1

double div2 = 3 / 2;
System.out.println("div2 = " + div2); //1.0

double div3 = 3.0 / 2;
System.out.println("div3 = " + div3); //1.5

double div4 = (double) 3 / 2;
System.out.println("div4 = " + div4); //1.5

int a = 3;
int b = 2;
double result = (double) a / b;
System.out.println("result = " + result); //1.5
```

### 자바에서 계산은 다음 2가지를 기억하자

1. **같은 타입끼리의 계산은 같은 타입의 결과를 낸다.**
   - `int + int` 는 `int` 를, `double + double` 은 `double` 의 결과가 나온다.
2. **서로 다른 타입의 계산은 큰 범위로 자동 형변환이 일어난다.**
   - `int + long` 은 `long + long` 으로 자동 형변환이 일어난다.
   - `int + double` 은 `double + double` 로 자동 형변환이 일어난다.

### 6-1. `double` 변수에 담아도 이미 늦었다 (`div2`)

```java
double div2 = 3 / 2;       //int / int
double div2 = 1;           //int / int이므로 int타입으로 결과가 나온다.
double div2 = (double) 1;  //int -> double에 대입해야 한다. 자동 형변환 발생
double div2 = 1.0;         // 1(int) -> 1.0(double)로 형변환 되었다.
```

**계산이 먼저, 대입이 나중**입니다. 계산 시점에 이미 소수점이 버려졌기 때문에 `double` 에 담아도 `1.0` 입니다.

### 6-2. 한쪽만 `double` 이면 된다 (`div3`, `div4`)

```java
double div3 = 3.0 / 2;              //double / int
double div3 = 3.0 / (double) 2;     //double / int이므로, double / double로 형변환이 발생한다.
double div3 = 3.0 / 2.0;            //double / double -> double이 된다.
double div3 = 1.5;

double div4 = (double) 3 / 2;       //명시적 형변환을 사용했다. (double) int / int
double div4 = (double) 3 / (double) 2; //double / int이므로, double / double로 형변환이 발생한다.
double div4 = 3.0 / 2.0;            //double / double -> double이 된다.
double div4 = 1.5;
```

### 6-3. 형변환 **위치**에 주의

형변환 `(double)` 은 **바로 뒤의 값 하나에만** 적용됩니다. 괄호로 계산을 감싸면 계산이 먼저 끝나 버립니다.

```java
int a = 3;
int b = 2;
double r1 = (double) a / b;    // O 1.5   - a 를 먼저 double 로 → double / int
double r2 = (double) (a / b);  // X 1.0   - a / b(=1) 를 먼저 계산 → 1 을 double 로
double r3 = a / (double) b;    // O 1.5
```

> 평균을 구할 때 가장 많이 하는 실수입니다.
> ```java
> int sum = 10;
> int count = 4;
> double avg = sum / count;          // X 2.0
> double avg2 = (double) sum / count; // O 2.5
> ```

## 7. 형변환으로 할 수 없는 것

### 7-1. 문자열 ↔ 숫자

캐스팅은 **숫자 타입끼리만** 가능합니다. 문자열과 숫자는 메서드를 사용해야 합니다.

```java
String s = "100";
int n = (int) s;                 // X 컴파일 에러
int n2 = Integer.parseInt(s);    // O 100

int num = 100;
String str = (String) num;       // X 컴파일 에러
String str2 = String.valueOf(num); // O "100"
String str3 = "" + num;            // O 문자열 더하기를 이용
```

### 7-2. `boolean` 은 숫자로 형변환 불가

```java
boolean flag = true;
int n = (int) flag;   // X 컴파일 에러: 자바의 boolean 은 0, 1 이 아님
```

## 8. 참고 - 축약 대입 연산자의 자동 형변환

`+=`, `-=` 같은 축약 대입 연산자는 **명시적 형변환을 자동으로** 해 줍니다. 편리하지만 소수점이 조용히 버려집니다.

```java
int i = 10;
i = i + 1.5;  // X 컴파일 에러: double 결과를 int에 넣을 수 없음
i += 1.5;     // O i = (int) (i + 1.5) → 11 (0.5 가 버려짐, 에러 없음)
```

## 9. 정리

**형변환**

- `int` → `long` → `double`
- 작은 범위에서 큰 범위로는 대입할 수 있다.
  - 이것을 묵시적 형변환 또는 자동 형변환이라 한다.
- 큰 범위에서 작은 범위의 대입은 다음과 같은 문제가 발생할 수 있다. 이때는 명시적 형변환을 사용해야 한다.
  - 소수점 버림
  - 오버플로우

**연산과 형변환**

- 같은 타입은 같은 결과를 낸다.
- 서로 다른 타입의 계산은 큰 범위로 자동 형변환이 일어난다.

### 체크리스트

- [ ] 큰 범위 → 작은 범위는 `(타입)` 명시적 형변환
- [ ] `(int)` 는 버림, 반올림은 `Math.round()`
- [ ] 형변환해도 원래 변수 값은 그대로
- [ ] 오버플로우는 에러가 안 남 → 결과를 계산하지 말고 **타입을 키워서 막자**
- [ ] 계산 결과가 클 수 있으면 계산 단계부터 `long` (`100000L * 100000`)
- [ ] `int / int` 는 `int` → 소수가 필요하면 한쪽을 `double` 로
- [ ] `(double) a / b` O, `(double) (a / b)` X
- [ ] 문자열 ↔ 숫자는 캐스팅이 아니라 `Integer.parseInt()`, `String.valueOf()`
