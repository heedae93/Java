## 한눈에 보기

| # | 주의사항 | 잘못 쓰면 |
|---|---|---|
| 1 | 메서드는 클래스 안, **다른 메서드 밖**에 정의 | 컴파일 에러 |
| 2 | 인수의 **개수, 타입, 순서**가 매개변수와 맞아야 한다 | 컴파일 에러 / 값이 뒤바뀜 |
| 3 | 반환 타입이 있으면 **모든 경로에서** `return` | `missing return statement` |
| 4 | `void` 메서드는 값을 받을 수 없다 | 컴파일 에러 |
| 5 | `return` 아래 코드는 실행되지 않는다 | `unreachable statement` / 의도한 코드 미실행 |
| 6 | **자바는 항상 변수의 값을 복사해서 대입한다** | 메서드 안에서 바꿔도 호출한 쪽 변수는 그대로 |
| 7 | 바뀐 값은 **반환받아서 다시 대입** | 계산 결과가 사라짐 |
| 8 | 다른 메서드의 지역 변수는 사용할 수 없다 | `cannot find symbol` |
| 9 | 큰 타입 → 작은 타입 매개변수는 명시적 형변환 | `possible lossy conversion` |
| 10 | 오버로딩은 **매개변수 타입/개수/순서**로만 구분 (반환 타입 X) | `already defined` 컴파일 에러 |
| 11 | 오버로딩 호출이 애매하면 컴파일 에러 | `reference to ... is ambiguous` |
| 12 | `switch` 안의 `break` 는 반복문을 빠져나가지 못한다 | 종료 메뉴를 골라도 계속 반복 |

## 1. 메서드가 필요한 이유

```java
// Method1 - 같은 계산을 두 번 작성
int a = 1;
int b = 2;
System.out.println(a + "+" + b + " 연산 수행");
int sum1 = a + b;

int x = 10;
int y = 20;
System.out.println(x + "+" + y + " 연산 수행");
int sum2 = x + y;
```

- 프로그램의 여러 곳에서 이와 같은 계산을 반복해야 한다면 같은 코드를 여러번 반복해서 작성해야 합니다.
- 어떤 연산을 수행하는지 출력하는 부분을 변경하거나 또는 제거하고 싶다면 해당 코드를 다 찾아다니면서 모두 수정해야 합니다.

```java
// Method1Ref - 메서드로 한 번 정의하고 계속 재사용
int sum1 = add(5, 10);
int sum2 = add(15, 20);

public static int add(int a, int b) {
    System.out.println(a + "+" + b + " 연산 수행");
    int sum = a + b;
    return sum;
}
```

> 핵심은 **메서드를 한번 정의해두면 계속해서 재사용할 수 있다**는 점입니다.

## 2. 메서드 정의

```java
제어자 반환타입 메서드이름(매개변수 목록) {
    메서드 본문
}

public static int add(int a, int b) {
    //메서드 본문, 실행 코드
}
```

| 구성 | 예 | 설명 |
|---|---|---|
| 제어자 (Modifier) | `public static` | 지금은 항상 `public static` 키워드를 입력하자. (뒤에서 설명) |
| 반환 타입 (Return Type) | `int` | 메서드가 실행 된 후 반환하는 데이터의 타입. 반환하지 않으면 `void` |
| 메서드 이름 (Method Name) | `add` | 이 이름으로 메서드를 호출한다 |
| 매개변수 (Parameter) | `(int a, int b)` | 메서드 내부에서 사용할 입력 값. 필요 없으면 `()` 로 비워둔다 |
| 메서드 본문 (Method Body) | `{ ... }` | 실제 메서드의 코드 |

- `public` : 다른 클래스에서 호출할 수 있는 메서드라는 뜻입니다. 접근 제어에서 학습합니다.
- `static` : 객체를 생성하지 않고 호출할 수 있는 정적 메서드라는 뜻입니다. 자세한 내용은 뒤에서 다룹니다.

> 주의: 지금 단계에서 `static` 을 빠뜨리면 `main()` 에서 호출할 때 `non-static method ... cannot be referenced from a static context` 컴파일 에러가 납니다.

### 2-1. 메서드는 다른 메서드 **밖**에 정의한다

```java
public class Method1Ref {
    public static void main(String[] args) {
        int sum1 = add(5, 10);

        public static int add(int a, int b) {  // X main 안에 정의 → 컴파일 에러
            return a + b;
        }
    }
}
```

```java
public class Method1Ref {
    public static void main(String[] args) {
        int sum1 = add(5, 10);
    }                                           // main 끝

    public static int add(int a, int b) {       // O 클래스 안, main 밖
        return a + b;
    }
}
```

> 메서드를 정의하는 **순서는 상관없습니다.** `add()` 가 `main()` 보다 아래에 있어도 호출할 수 있습니다.

## 3. 인수와 매개변수

```
호출: call("hello", 20)
메서드 정의: int call(String str, int age)
```

- **인수(Argument)**: `"hello"`, `20` 처럼 넘기는 값. 인수는 '인'과 '수'의 합성어로 '들어가는 수'라는 의미를 가진다. 즉, 메서드 내부로 들어가는 값을 의미한다. 인자도 같은 의미이다.
- **매개변수(Parameter)**: 메서드를 정의할 때 선언한 변수인 `String str`, `int age`. '매개'와 '변수'의 합성어로 '중간에서 전달하는 변수'라는 의미를 가진다. 즉, 메서드 호출부와 메서드 내부 사이에서 값을 전달하는 역할을 하는 변수라는 뜻이다.

### 3-1. 개수, 타입, 순서가 맞아야 한다

메서드를 호출할 때는 메서드에 넘기는 값과 매개변수(파라미터)의 **타입**이 맞아야 합니다. 물론 넘기는 값과 매개변수(파라미터)의 **순서와 갯수**도 맞아야 합니다.

```java
int call(String str, int age)

call("hello", 20);   // O
call(20, "hello");   // X 순서가 다름 → 컴파일 에러
call("hello");       // X 개수가 다름 → 컴파일 에러
```

> 주의: **같은 타입끼리 순서를 바꾸면 컴파일 에러가 나지 않습니다.**
> ```java
> int withdraw(int balance, int amount)
>
> withdraw(2000, balance);  // 컴파일은 되지만 잔액 자리에 2000, 금액 자리에 잔액이 들어감!
> ```
> 매개변수의 순서를 정의와 꼭 비교해 보세요.

## 4. 반환 타입과 `return`

### 4-1. 반환 타입이 있으면 반드시 값을 반환해야 한다

반환 타입이 있는 메서드는 반드시 `return` 을 사용해서 값을 반환해야 합니다. 이 부분은 특히 **조건문과 함께 사용할 때** 주의해야 합니다.

```java
// MethodReturn1 - X
public static boolean odd(int i) {
    if (i % 2 == 1) {
        return true;
    }
    // 조건을 만족하지 않으면 return 이 없음!
}
```

```
java: missing return statement
```

```java
// O
public static boolean odd(int i) {
    if (i % 2 == 1) {
        return true;
    } else {
        return false;
    }
}

// O 더 간단하게
public static boolean odd(int i) {
    return i % 2 == 1;
}
```

> `if ~ else if` 만 있고 `else` 가 없거나, `switch` 에 `default` 가 없을 때도 같은 에러가 납니다. 컴파일러 입장에서는 **모든 경우에 return 이 있는지** 확인할 수 없기 때문입니다.

### 4-2. `void` 메서드

```java
public static void printHeader() {
    System.out.println("= 프로그램을 시작합니다 =");
    return; //void의 경우 생략 가능
}
```

- 반환 타입이 없는 경우 `void` 로 정의합니다.
- 모든 메서드는 항상 `return` 을 호출해야 합니다. 그런데 반환 타입 `void` 의 경우에는 예외로 생략해도 됩니다. 자바가 반환 타입이 없는 경우에는 `return` 을 마지막줄에 넣어줍니다.

```java
String str = printHeader();               // X 컴파일 에러: void 는 반환 값이 없음
System.out.println(printHeader());        // X 컴파일 에러: 출력할 값이 없음
printHeader();                            // O
```

```java
public static void printHeader() {
    return "hello";   // X 컴파일 에러: void 메서드는 값을 반환할 수 없음
}
```

### 4-3. `return` 을 만나면 즉시 메서드를 빠져나간다 (`MethodReturn2`)

```java
public static void checkAge(int age) {
    if (age < 18) {
        System.out.println(age + "살, 미성년자는 출입이 불가능합니다.");
        return;       // 여기서 메서드 종료 → 아래 코드 실행 안 함
    }
    System.out.println(age + "살, 입장하세요.");
}
```

`return` 을 빠뜨리면 미성년자에게도 "입장하세요." 가 출력됩니다.

```java
return sum;
System.out.println("끝");   // X 컴파일 에러: unreachable statement (도달할 수 없는 코드)
```

### 4-4. 반환 값은 무시할 수 있다 - 하지만 주의

```java
int sum = add(1, 2);  //반환된 값을 받아서 sum에 저장했다.
add(1, 2);            //반환된 값을 사용하지 않고 버린다.
```

반환 값을 무시해도 컴파일 에러는 나지 않습니다. 그래서 **값을 받아야 하는 메서드의 결과를 버리는 실수**를 해도 알려주지 않습니다. (6장 참고)

## 5. 메서드 실행이 끝나면 지역 변수는 사라진다

메서드 호출이 끝나면 더 이상 해당 메서드가 사용한 메모리를 낭비할 이유가 없습니다. 메서드 정의에 사용한 파라미터 변수인 `int a`, `int b` 는 물론이고, 그 안에서 정의한 `int sum` 도 모두 제거됩니다.

```java
public static void main(String[] args) {
    int balance = 10000;
    deposit(1000);
}

public static void deposit(int amount) {
    balance += amount;   // X 컴파일 에러: cannot find symbol - balance 는 main 의 지역 변수
}
```

필요한 값은 **매개변수로 전달**하고, 결과는 **반환**받아야 합니다. (`MethodEx3Ref`)

```java
public static int deposit(int balance, int amount) {
    balance += amount;
    return balance;
}
```

## 6. 자바는 항상 변수의 값을 복사해서 대입한다 ⚠️

**이 대원칙은 반드시 이해해야 합니다.** 그러면 아무리 복잡한 상황에도 코드를 단순하게 이해할 수 있습니다.

### 6-1. 변수와 값 복사 (`MethodValue0`)

```java
int num1 = 5;
int num2 = num1;  // num1 의 값 5 를 읽고 복사해서 num2 에 넣는다
num2 = 10;
// num1=5, num2=10
```

`num1` 이라는 변수 자체가 `num2` 에 들어가는 것이 아닙니다. `num1` 에 들어있는 값을 읽고 복사해서 `num2` 에 넣는 것입니다.

### 6-2. 메서드 호출과 값 복사 (`MethodValue1`)

```java
public static void main(String[] args) {
    int num1 = 5;
    System.out.println("1. changeNumber 호출 전, num1: " + num1);
    changeNumber(num1);
    System.out.println("4. changeNumber 호출 후, num1: " + num1);
}

public static void changeNumber(int num2) {
    System.out.println("2. changeNumber 변경 전, num2: " + num2);
    num2 = num2 * 2;
    System.out.println("3. changeNumber 변경 후, num2: " + num2);
}
```

```
1. changeNumber 호출 전, num1: 5
2. changeNumber 변경 전, num2: 5
3. changeNumber 변경 후, num2: 10
4. changeNumber 호출 후, num1: 5     ← 10 이 아니다!
```

혹시라도 실행 결과의 마지막이 10이라고 생각했다면 대원칙을 떠올려보자.

- `changeNumber(num1)` 호출 시점에 `num1` 의 값 5 를 읽고 **복사해서** `num2` 에 전달합니다.
- `num2` 의 변경은 `num1` 에 영향을 주지 않습니다. 앞서 값을 복사해서 전달했기 때문입니다.

### 6-3. 이름이 같아도 다른 변수다 (`MethodValue2`)

```java
public static void main(String[] args) {
    int number = 5;
    changeNumber(number);
    System.out.println(number);   // 5
}

public static void changeNumber(int number) {
    number = number * 2;          // changeNumber 의 number 만 10
}
```

`main()` 도 사실은 메서드입니다. 각각의 메서드 안에서 사용하는 변수는 서로 완전히 분리된 다른 변수입니다. 물론 **이름이 같아도 완전히 다른 변수**입니다.

### 6-4. 값을 바꾸려면 반환받아서 대입한다 (`MethodValue3`)

```java
int num1 = 5;
num1 = changeNumber(num1);   // 반환 값을 다시 num1 에 대입
// num1 = 10

public static int changeNumber(int num2) {
    num2 = num2 * 2;
    return num2;
}
```

### 6-5. 가장 흔한 실수 - 반환 값을 받지 않음 (`MethodEx3Ref`)

```java
int balance = 10000;
deposit(balance, 1000);              // X 반환 값을 버림 → balance 는 여전히 10000
balance = deposit(balance, 1000);    // O balance = 11000
```

`deposit()` 안에서 출력되는 "현재 잔액: 11000원" 을 보고 잘 동작한다고 착각하기 쉽습니다. **호출한 쪽의 `balance` 는 바뀌지 않았습니다.**

> 참고로 뒤에서 참조형이라는 것을 학습하는데, 이때도 똑같다. 결국 참조형 변수에 있는 값인 **참조값을 복사**하는 것이다! 이것은 나중에 알아본다.
> 미리 보기: 배열을 넘기면 참조값이 복사되므로, 메서드 안에서 `arr[0] = 100;` 처럼 **배열의 내용**을 바꾸면 호출한 쪽에서도 바뀐 것이 보입니다.

## 7. 메서드와 형변환

메서드를 호출하는데 인자와 매개변수의 타입이 맞지 않으면 어떻게 해야할까? 메서드를 호출할 때 매개변수에 값을 전달하는 것도 결국 변수에 값을 대입하는 것입니다. 따라서 **앞서 배운 형변환 규칙이 그대로 적용**됩니다.

### 7-1. 큰 타입 → 작은 타입: 명시적 형변환 (`MethodCasting1`)

```java
double number = 1.5;
//printNumber(number);       // double을 int형에 대입하므로 컴파일 오류
printNumber((int) number);   // 명시적 형변환을 사용해 double을 int로 변환
// 숫자: 1   (1.5 → 1, 소수점 버림)

public static void printNumber(int n) {
    System.out.println("숫자: " + n);
}
```

```
java: incompatible types: possible lossy conversion from double to int
```

### 7-2. 작은 타입 → 큰 타입: 자동 형변환 (`MethodCasting2`)

```java
int number = 100;
printNumber(number);   // int에서 double로 자동 형변환
// 숫자: 100.0

public static void printNumber(double n) {
    System.out.println("숫자: " + n);
}
```

> 정리: 메서드를 호출할 때는 전달하는 인수의 타입과 매개변수의 타입이 맞아야 합니다. 단 타입이 달라도 자동 형변환이 가능한 경우에는 호출할 수 있습니다.

### 7-3. 반환 값에도 형변환 규칙이 적용된다

```java
public static int average(int a, int b, int c) {
    return (a + b + c) / 3.0;   // X 컴파일 에러: double 을 int 로 반환할 수 없음
}

public static double average(int a, int b, int c) {
    int sum = a + b + c;
    return sum / 3;             // X 컴파일은 되지만 int / int → 소수점 버림 (6 / 3 은 괜찮지만 7 / 3 → 2.0)
}

public static double average(int a, int b, int c) {   // O MethodEx1Ref
    int sum = a + b + c;
    return sum / 3.0;
}
```

## 8. 메서드 오버로딩

이름이 같고 매개변수가 다른 메서드를 여러개 정의하는 것을 **메서드 오버로딩(Overloading)** 이라 합니다. 오버로딩은 번역하면 과적인데, 과하게 물건을 담았다는 뜻입니다.

```java
add(int a, int b)
add(int a, int b, int c)
add(double a, double b)
```

### 8-1. 오버로딩 규칙 - 반환 타입은 인정하지 않는다

메서드의 이름이 같아도 **매개변수의 타입 및 순서가 다르면** 오버로딩을 할 수 있습니다. 참고로 **반환 타입은 인정하지 않습니다.**

```java
// X 오버로딩 실패 - 메서드 이름과 매개변수의 타입이 같으므로 컴파일 오류
int add(int a, int b)
double add(int a, int b)
```

**메서드 시그니처(method signature)**

```
메서드 시그니처 = 메서드 이름 + 매개변수 타입(순서)
```

- 메서드 시그니처는 자바에서 메서드를 구분할 수 있는 고유한 식별자나 서명을 뜻합니다.
- 메서드 이름이 같아도 메서드 시그니처가 다르면 다른 메서드로 간주합니다.
- **반환 타입은 시그니처에 포함되지 않습니다.**

> 주의: **매개변수의 이름**도 시그니처에 포함되지 않습니다.
> ```java
> int add(int a, int b)
> int add(int x, int y)   // X 이름만 다르고 타입이 같음 → 컴파일 에러
> ```

### 8-2. 어떤 메서드가 호출될까?

**먼저 본인의 타입에 최대한 맞는 메서드를 찾아서 실행하고, 그래도 없으면 형 변환 가능한 타입의 메서드를 찾아서 실행합니다.**

```java
// Overloading3
public static int add(int a, int b)          // 1번
public static double add(double a, double b) // 2번

add(1, 2);      // 1번 호출 → 3
add(1.2, 1.5);  // 2번 호출 → 2.7
```

여기서 1번 `add(int a, int b)` 를 삭제하면?

```java
add(1, 2);      // int → double 자동 형변환 → 2번 호출 → 3.0
```

결과가 `3` 에서 `3.0` 으로 바뀝니다. 메서드를 지우거나 추가하면 **다른 메서드가 호출될 수 있다**는 점에 주의하세요.

### 8-3. 애매한 호출은 컴파일 에러 (`Overloading2`)

```java
public static void myMethod(int a, double b)
public static void myMethod(double a, int b)

myMethod(1, 1.2);  // O int a, double b
myMethod(1.2, 2);  // O double a, int b
myMethod(1, 2);    // X 컴파일 에러: reference to myMethod is ambiguous
```

`myMethod(1, 2)` 는 두 메서드 모두 형변환으로 호출할 수 있어서, 자바가 어느 쪽을 선택해야 할지 결정할 수 없습니다.

## 9. `switch` 안에서 반복문 종료하기 (`MethodEx4`)

```java
while (true) {
    int choice = scanner.nextInt();
    switch (choice) {
        case 1:
            balance = deposit(balance, amount);
            break;                // switch 만 빠져나감
        ...
        case 4:
            System.out.println("시스템을 종료합니다.");
            return;               // main 메서드 자체를 종료 → 반복도 끝
        default:
            System.out.println("올바른 선택이 아닙니다. 다시 선택해주세요.");
    }
}
```

`case 4` 에서 `break` 를 쓰면 `switch` 만 빠져나가고 `while (true)` 는 계속 돕니다. 여기서는 `return` 으로 **메서드를 끝내서** 반복문도 함께 종료합니다.

> `return` 은 `main()` 에서도 똑같이 "메서드를 즉시 빠져나간다" 는 의미입니다. `main()` 이 끝나면 프로그램이 종료됩니다.

## 10. 메서드 이름 짓기

변수 이름은 일반적으로 명사를 사용합니다. 한편 메서드는 무언가 동작하는데 사용하기 때문에 일반적으로 **동사로 시작**합니다.
이런 차이점 외에는 변수 이름과 메서드 이름에 대한 규칙은 둘다 같습니다. (소문자로 시작, 낙타 표기법)

| 구분 | 예 |
|---|---|
| 변수명 | `customerName`, `totalSum`, `employeeCount`, `isAvailable` |
| 메서드명 | `printReport()`, `calculateSum()`, `addCustomer()`, `getEmployeeCount()`, `setEmployeeName()` |

> 메서드 이름만 보고 무슨 일을 하는지 알 수 있어야 합니다. `average()`, `deposit()`, `withdraw()` 처럼 이름 덕분에 `main()` 이 책의 목차처럼 읽힙니다.

## 11. 메서드 추출 (Extract Method)

`MethodEx3` → `MethodEx3Ref` 처럼 코드를 메서드로 분리하는 리팩토링을 **메서드 추출(Extract Method)** 이라 합니다.

- 메서드를 재사용하는 목적이 아니어도 괜찮습니다. 메서드를 적절하게 사용해서 분류하면 구조적으로 읽기 쉽고 유지보수 하기 좋은 코드를 만들 수 있습니다.
- `main()` 은 세세한 코드가 아니라 전체 구조를 한눈에 볼 수 있게 됩니다. 쉽게 이야기해서 책의 목차를 보는 것 같습니다.
- 변경 사항이 발생하면 관련된 메서드만 수정하면 됩니다. 메서드별로 수정 범위가 한정되기 때문에 더 유지보수 하기 좋습니다.

> IntelliJ 단축키: 코드를 드래그한 뒤 `Ctrl + Alt + M` 으로 메서드 추출

## 12. 정리 체크리스트

- [ ] 메서드는 클래스 안, 다른 메서드 밖에 정의 (지금은 `public static`)
- [ ] 인수의 개수, 타입, **순서**가 매개변수와 맞는가? (같은 타입끼리 순서 바뀜 주의)
- [ ] 반환 타입이 있으면 모든 경로(`if`/`else`)에서 `return`
- [ ] `void` 메서드는 값을 반환하지도, 받지도 않는다
- [ ] `return` 을 만나면 즉시 메서드 종료
- [ ] **자바는 항상 값을 복사해서 전달** → 매개변수를 바꿔도 호출한 쪽은 그대로
- [ ] 바뀐 값은 `balance = deposit(balance, 1000);` 처럼 반환받아 대입
- [ ] 다른 메서드의 지역 변수는 사용 불가 → 매개변수로 전달
- [ ] `double` → `int` 매개변수는 명시적 형변환, `int` → `double` 은 자동
- [ ] 오버로딩은 매개변수로만 구분 (반환 타입, 매개변수 이름 X)
- [ ] 반복문 안 `switch` 에서 종료하려면 `return` (또는 다른 방법)
- [ ] 메서드 이름은 동사로 시작
